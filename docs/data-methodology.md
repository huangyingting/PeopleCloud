# 人物数据方法与不确定性

## 收录口径

当前版本是“跨时代、跨领域的策展型样本”，收录 248 位人物。14 个浏览时期均有至少 13 位人物；本轮对每个时期等量增加 5 人，汉、唐、宋、明、清现分别覆盖 19、23、23、23、26 位。同时兼顾思想、政治、军事、文学、艺术、科技、医学、探索与女性人物。界面始终使用“收录”而不是“共计”，避免暗示穷尽。

## 扩充选择原则

- 先补入跨教材、博物馆叙事与公共历史中反复出现的标志性人物，再补齐长期被帝王将相叙事遮蔽的医学、科技、艺术、女性和跨区域交流人物。
- 不以最终“每朝同数”为目标：秦、隋、五代等短时期仍保持相对紧凑，汉、唐、宋、明、清按历史跨度和文化门类保留更高总量；本轮采用每时期等量新增，专门防止长时期吸收全部扩充资源。
- “著名”不是可计算的绝对全集。本项目保留策展边界，不声称列出全部历史人物，也不以视觉填充为理由加入资料不足的名字。
- 一个跨朝代人物只放入最有助于浏览的时期；`periodId` 是产品导航归类，不替代完整的学术断代判断。

## 时间字段

- `bornYear` / `diedYear`：内部排序锚点，公元前使用负数；不详可为空。
- `lifespan`：面向用户的诚实表述，可使用“约”“前”“不详”等文字。
- `periodId`：产品浏览时期，不等同于对复杂政权归属的唯一学术判断。

## 地理字段

每个点必须同时包含地点名、经纬度、关系和置信度：

- `birthplace`：出生地；若学界有争议，必须在 `placeNote` 中说明。
- `ancestral_home`：籍贯或郡望，不可显示为出生地。
- `active`：长期活动、创作或主要事业地点。
- `office`：主要任职地点。
- `capital`：与政治活动密切相关的都城锚点。
- `memorial`：墓祠或纪念地，仅在它确实是产品要表达的关系时使用。

置信度为 `high | medium | disputed`。`disputed` 点必须有可见说明。坐标用于视图聚焦而非测绘或遗址界定。

## 简介与来源

简介采用原创短摘要，不复制来源长段落。每位人物至少提供一个公开 HTTPS 参考入口；当前统一提供结构稳定的中文百科条目，便于继续阅读和交叉核对，后续可逐条补充中国大百科全书、故宫博物院、国家博物馆、联合国教科文组织或 Britannica 等机构来源。来源不代表页面逐字引用。

## 校验与变更

`npm run verify:data` 会检查：

- 总量不得低于 248，所有产品时期必须达到扩充后的分期最低人数；
- 唯一 ID、合法生卒范围、经纬度范围和时期对应关系；
- 简介、成就、别名和检索关键字的最低质量；
- 地理关系、置信度和争议说明之间的一致性；
- 来源必须为 HTTPS 且提供标题；
- 显式人物关系只能指向存在的人物，不能自指。

命令还会输出逐时期和逐领域覆盖数，使内容扩充是否真的改善广度可以被审计，而不只依赖页面上的总数。

`npm run verify:sources` 以低并发联网检查全部来源的 HTTP 可达性。该检查不并入离线构建门禁，避免外部站点临时故障使正常构建失效。

内容扩充时先补证据和语义，再加坐标。禁止为了视觉分散而随机移动重复地点。
